# 出流前产品状态读取引导设计

## 目标

在手动 CAN 调试工具中执行 `Set DUT Current 0 A` 之前，先读取并展示产品内部状态，供操作者人工确认。工具只负责读取和展示，不判断条件是否合格，不限制操作者继续发送 0A 指令。

## 触发方式

操作者在 SEQ 顺序列表中选择 `Set DUT Current 0 A` 并点击“执行当前步骤”时：

1. 暂不发送 DUT 电流指令。
2. 自动通过产品 CAN 依次读取状态值。
3. 弹出“出流前产品状态”窗口。
4. 操作者可以重新读取、确认并发送 0A，或者取消。

其他 DUT 电流步骤保持现有行为，不自动弹出该窗口。

## 读取项目

| 页面名称 | 读取方式 | 单位 |
|---|---|---|
| 产品母线高压 | `AddrOffset=0, TableIndex=184, DataSize=4` | V |
| Battery 电压 | `AddrOffset=0, TableIndex=128, DataSize=4` | V |
| PSR 电压 | `AddrOffset=0, TableIndex=84, DataSize=4` | V |
| HVDC_OV_FLT | `AddrOffset=24, TableIndex=1, DataSize=1` | 无 |
| OV_FLT | `AddrOffset=24, TableIndex=19, DataSize=1` | 无 |
| 产品板温 | `AddrOffset=0, TableIndex=68, DataSize=4` | ℃ |

不读取水流、冷却液入口温度或冷却液出口温度。

## 页面行为

弹窗以表格形式显示项目名称、读取值、单位和读取状态。

- 成功时显示解析后的十进制值，例如 `618.3 V`、`24.12 V`、`0`。
- 失败时显示“读取失败”及简短错误信息。
- 不显示上下限、PASS/FAIL 或合格颜色。
- 不根据读取值启用或禁用“确认并发送0A”。

按钮行为：

- `重新读取`：再次读取全部项目并刷新页面。
- `确认并发送0A`：关闭弹窗并调用现有 `SetDutCurrent`，使用当前页面上的步骤值、步进电流、保持时间和频率。
- `取消`：关闭弹窗，不发送电流指令。

## 日志行为

现有产品 CAN 原始报文日志继续保留，包括每次读取产生的 `Product TX` 和 `Product RX`。

每个项目读取结束后，再追加一条解析值日志，例如：

```text
读取产品母线高压：618.3 V
读取Battery电压：24.12 V
读取PSR电压：23.98 V
读取HVDC_OV_FLT：0
读取OV_FLT：1
读取产品板温：26.5 ℃
```

读取失败时记录项目名称和失败原因，但不自动发送 0A，也不替操作者作出判断。

## 代码边界

- `ManualCanDebug.Core` 提供一次读取全部项目的服务方法，并返回结构化结果，不包含 WPF 类型。
- WPF 项目负责弹窗、重新读取以及操作者最终选择。
- 现有 `ReadDutValue` 和底层 CAN 收发继续复用，确保日志中保留原始报文。
- 只有 `Set DUT Current 0 A` 的执行路径插入引导流程，其余电流指令和产品 CAN 功能不改动。

## 错误处理

- 产品 CAN 未连接或 DUT 尚未初始化时，读取结果显示失败原因，不伪造数值。
- 单个项目读取失败不终止其他项目读取。
- 读取期间禁用重复操作按钮，完成后恢复。
- 窗口关闭或取消时不得发送 0A 指令。

## 验证要求

- 单元测试覆盖读取项目的名称、地址参数、单位和固定顺序。
- 单元测试覆盖单项失败时仍继续读取后续项目。
- WPF 执行路径测试或可测试控制逻辑证明：只有操作者确认后才发送 0A，取消时不发送。
- 完整解决方案在 .NET Framework 4.8、x86 下成功编译。
- 使用实际产品验证页面解析值与日志原始 CAN 报文同时出现。
